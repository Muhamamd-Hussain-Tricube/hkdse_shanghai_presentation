## Working Style

Operate autonomously — make reasonable decisions without asking for permission unless a credential (API key, secret) is needed. In development, it is safe to clear database records between test runs.

After every change, verify in this order:
1. **Build check** — `npm run build`
2. **Feature verification** — for UI changes, test the feature directly in the browser; for logic changes, confirm via code-level inspection or by exercising the relevant Supabase function.

## Commands

```bash
npm run dev          # start Vite dev server
npm run build        # production build (also used as a post-change sanity check)
npm run lint         # ESLint
npm run format       # Prettier
```

There is no test suite. Verification is build + manual browser testing.

### Supabase

The Supabase project ID is `poapnhnyzwgvmmccjefq`. Apply schema changes and deploy edge functions using the Supabase CLI:

```bash
# Apply all pending migrations
supabase db push

# Deploy a single edge function
supabase functions deploy <function-name>

# Deploy all edge functions
supabase functions deploy

# Generate updated TypeScript types after schema changes
supabase gen types typescript --project-id poapnhnyzwgvmmccjefq > src/integrations/supabase/types.ts
```

Edge functions live under `supabase/functions/<name>/index.ts` and are written in Deno (not Node). They import from `https://esm.sh/` and share utilities via `supabase/functions/_shared/`. All four functions (`generate-test`, `grade-test`, `analyze-interview`, `generate-report`) have `verify_jwt = false` in `supabase/config.toml` and handle CORS manually.

## Architecture

### Stack

- **Framework**: TanStack Start (React 19 + TanStack Router) compiled with Vite; deployed to Cloudflare Workers via `@cloudflare/vite-plugin`.
- **Backend**: Supabase (Postgres + Auth + Edge Functions). AI calls inside edge functions use Google Gemini via `supabase/functions/_shared/gemini.ts`.
- **Styling**: Tailwind CSS v4 + shadcn/ui (Radix primitives). Component config is in `components.json`.
- **i18n**: i18next with two locales: `src/locales/en.ts` and `src/locales/zh-Hans.ts`.

### Auth & Roles

`src/lib/auth-context.tsx` — `AuthProvider` wraps the whole app. It exposes `user`, `session`, `organizations` (list of `OrgMembership`), and `activeOrgId`. On first login, `ensureUserOrganization` auto-creates an org.

Database roles (`app_role` enum): `super_admin | org_admin | parent | student`. RLS is enforced via `has_role()` and `is_org_member()` Postgres functions.

### Routing

File-based routes under `src/routes/`. Two main subtrees:

- `/dashboard/*` — org-admin views (cases list, invitations, settings). Protected by `beforeLoad` redirect if no session.
- `/parent/$caseId/*` — parent/student-facing pipeline. Each sub-route is a pipeline stage (profile → tests → interview → results → report).

`routeTree.gen.ts` is auto-generated by the TanStack Router plugin on `npm run dev` — do not edit it.

### Data Model (key tables)

| Table | Purpose |
|---|---|
| `organizations` | Advisory firms; have a `calendly_url` for scheduling |
| `organization_members` | Links users to orgs with `is_owner` flag |
| `student_cases` | One case per student; drives the advisory pipeline via `case_status` enum |
| `case_test_assignments` | Which tests are assigned to a case (`test_type` enum: `hk_aptitude \| ielts_practice \| curriculum_fit`) |
| `test_sessions` | Actual test attempt; holds questions/answers JSON and grading results |
| `interviews` | Scheduled or uploaded interview; stores transcript and `ai_analysis` JSON |
| `invitations` | Org invite tokens sent to parents |

`case_status` enum defines the pipeline order: `profile_incomplete → profile_complete → test_in_progress → test_completed → interview_scheduled → interview_completed → transcript_ready → report_draft → report_published`.

### Client-Side Patterns

- **Supabase client**: singleton lazy proxy at `src/integrations/supabase/client.ts`. Import as `import { supabase } from "@/integrations/supabase/client"`.
- **Types**: `src/integrations/supabase/types.ts` is generated — regenerate after any schema migration.
- **Case progress logic**: `src/lib/case-progress.ts` contains pure functions for computing pipeline stage, assignment display status, and required profile fields.
- **Path alias**: `@/` maps to `src/`.
- **Vite config**: `vite.config.ts` defers entirely to `@lovable.dev/vite-tanstack-config`. Do not manually add plugins that are already included by that preset (TanStack Start, React, Tailwind, tsConfigPaths, Cloudflare, `@` alias — see comments in the file).
